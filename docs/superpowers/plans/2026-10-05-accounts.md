# Accounts and Server-Held Data Implementation Plan

> **For agentic workers:** Implement task by task. Steps use checkbox (`- [ ]`) syntax. **Never commit**: the owner commits. Run `npm test`, `npm run lint` and `npm run build` yourself at the end of your phase.

**Goal:** Users register and confirm their email; their data, calendar subscription and email digest live on the server under their account, so every device and every import stays in sync.

**Architecture:** Hand-rolled auth on `node:crypto` behind an `AccountStore` interface (memory + Upstash Redis implementations). One versioned data document per user with compare-and-set saves; the client keeps zustand as the in-memory model, syncs with debounce and three-way merges on conflict. The calendar and digest read the account's data directly.

**Tech Stack:** Next.js 16 (App Router, `proxy.ts`; read `node_modules/next/dist/docs/` before using route handlers, cookies or proxy), React 19, zustand 5, `@upstash/redis`, Resend via fetch, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-05-accounts-design.md` (read it first; it holds the key layout, flows, limits and copy).

## Global Constraints

- No new dependencies. Hashing: `scrypt` N=2^15, r=8, p=1, keylen 64, salt 16 bytes, format `scrypt$N$r$p$salt$hash` (base64url); compare with `timingSafeEqual`.
- Password length 10–200. Tokens: 32 random bytes base64url, stored as sha256 only. Expiry: confirm 48 h, magic 30 min, reset 30 min, email-change 48 h. Sessions 90 days, slid at most once per 24 h.
- Cookie `hr_session`: httpOnly, Secure in production, SameSite=Lax, Path=/, Max-Age 90 days. Mutating `/api/fiok*` and `/api/adatok` routes reject a mismatching `Origin` with 403.
- Rate limits: register 5/h/IP; login 10/15 min/IP and 5/15 min/email; magic link and reset 3/h/email and 10/h/IP. 429 copy: "Túl sok próbálkozás, próbáld újra később".
- Data document cap 900 KB serialized (413). Caps from `lib/server/subscription.ts`: 20 feeds, 1500 class sessions, 2000 ignored pairs.
- All UI text and error messages Hungarian; code and comments English. Follow CLAUDE.md conventions (tokens, `components/ui/*`, lucide icons, Hirdetőtábla). Tests import only modules free of React, zustand and `"use client"`.
- Server logs never contain emails, passwords, tokens or session ids.
- Email links only open a page (`/fiok/link?m=…&t=…`); only a POST consumes a token.

## Review Focus

1. **Email case and whitespace** ("Anna@X.hu " vs "anna@x.hu"): the same account everywhere (register, login, magic, reset, email change). Test in Task 2.
2. **Reusing a link** (double click, mail scanner GET): the second POST fails cleanly with "A link lejárt vagy már felhasználták", and a GET never consumes. Test in Task 2 (consume twice) and Task 3 (GET page doesn't call consume).
3. **Two devices saving at once:** neither change is lost when they touch different items. Test in Task 5 (merge) and Task 4 (CAS conflict returns remote).
4. **Signing in as a different user on the same browser:** the previous user's cached data never shows or uploads into the new account. Test in Task 6 (`resolveStartupData` owner mismatch).
5. **Calendar right after an edit:** a save invalidates the rendered `.ics` cache, so a calendar refresh shows the change immediately. Test in Task 7.
