# Project conventions

The current roadmap (what's done, what's next, open questions) is in `docs/PLAN.md`; read it at the start of a session and keep it updated. Real iCal exports for tests go in `fixtures/ical/` (scrubbed, see its README).

Hallgatói réteg: a per-course dashboard that sits on top of university systems (Neptun, Teams, Canvas, Moodle, TMS, Discord…).

- **Language:** all UI text is Hungarian; code, identifiers and comments are English. Routes are Hungarian (`/`, `/targy/[id]`, `/radar`, `/beallitasok`).
- **Local-first:** no accounts, no auth. All data lives in the zustand store `lib/store.ts`, persisted to localStorage (`hallgatoireteg-v1`). Types are in `lib/types.ts`. Select slices individually: `useStore((s) => s.courses)`.
- **Hydration:** components that read the store are client components and render a skeleton until `useHydrated()` (`lib/useHydrated.ts`) returns true.
- **Dynamic routes:** `page.tsx` is a thin server component that awaits `params` (typed with `PageProps<"/route/[id]">`) and renders a client component (e.g. `app/targy/[id]/page.tsx` → `components/week/CourseWeekDetail.tsx`).
- **UI:** Tailwind v4 with the color tokens from `app/globals.css` (`bg-card`, `border-border`, `text-muted`, `bg-accent`, `text-danger`…). Build from `components/ui/*` and use `lucide-react` icons. No component libraries, and no new dependencies without asking.
- **Platforms:** built-in platforms are in `lib/platforms.ts`, and user-defined ones in `customPlatforms`. Always resolve them with `getPlatform(id, customPlatforms)`. Normalise user URLs with `normalizeLinkUrl` (`lib/url.ts`).
- **Deadlines:** urgency, week grouping and the weekly summary are pure functions in `lib/radar.ts` (weeks start on Monday). Reuse them; don't recompute urgency in components. Deadlines with `source: "ical"` can't be edited or deleted, only marked done or critical.
- **iCal:** `app/api/ical/route.ts` is a CORS proxy (fetching lives in `lib/ical/fetch.ts`, shared with the subscription routes). Every URL, and every redirect hop, must pass `assertPublicUrl` (`lib/ical/ssrf.ts`); never remove that check or switch to `redirect: "follow"`. Parsing (`lib/ical/parse.ts`) and course matching (`lib/ical/match.ts`) are pure functions. Sync goes through `lib/ical/client.ts` → the store's `applyFeedSync` (a thin wrapper over the pure `mergeFeedSync` in `lib/ical/sync.ts`, also used by the server), which upserts by `(feedId, externalUid)` and keeps the user's `done`/`critical`/course choices. Canvas context parsing lives in `lib/ical/canvas.ts`, discovery in `lib/ical/discover.ts` + the store's `applyDiscovery`; matching is longest-keyword-wins.
- **Search & quick-add:** search lives in `lib/search.ts` + `components/CommandPalette.tsx`, the quick-add parser in `lib/quickAdd.ts`; matching is accent-insensitive via `normalizeSearch` (`lib/text.ts`).
- **Dialogs:** `components/ui/Dialog.tsx` mounts its children only while open, so forms inside it initialise from props with `useState(initial…)`.
- **Design system:** "Hirdetőtábla" (faculty notice board), in daylight (light) and after hours (dark). Tokens in `app/tokens.css`, one block per theme on `[data-theme]` (light is `:root`); hover tints use `bg-wash/[…]`, never `bg-black/…`; shadows, backdrop and canvas inks are tokens too. The preference (`theme`: system | light | dark, default system) is a store device preference, applied before paint by `THEME_SCRIPT` (`lib/theme.ts`) in the root layout and kept in sync by `ThemeSync`; toggle in the header (`ThemeToggle`) and Beállítások → Megjelenés (felt `--bg`, copy-paper `--panel`, toner `--accent` for primary buttons and active controls with `text-accent-ink` on it, red `--pin` / `--danger` only for now, late, critical and destructive, coloured papers `--canary` (today, highlight), `--salmon` (overdue), `--sky` (classes)), mapped to Tailwind colours in `globals.css`. Font: Archivo via next/font; headings use `.font-display` (condensed, heavy). Primitives in `globals.css`: `.pin` (round head, colour via `--pin-color`), `.slip` (a pinned paper slip; `data-done` unpins and tilts it), `.sheet-paper`. Deadlines on boards are `DeadlineChip` slips whose pin carries state (course colour, red when hot, gone when done). Pages use `SectionHeading` (title + optional sub + actions; no eyebrows or kickers), `Card`, `Pill`, `Dialog`, `EmptyState` from `components/ui/`; `PinboardField` is the canvas background (one faint slip per open deadline, each in a fixed slot; ticking off takes the latest down, unticking or adding pins one up). No raw hex outside user/course/platform data and `PinboardField`; no gradients, glows or glass; copy is concise, professional Hungarian with no jokey asides; respect `prefers-reduced-motion`.
- **Calendar subscription (the only server state, opt-in):** `buildCalendar` (`lib/ical/export.ts`, pure, ical.js) renders one merged .ics; `downloadCalendar()` does it in the browser with no server. Subscribing uploads a snapshot (courses, deadlines, feeds, customPlatforms, export options) via `lib/subscription/client.ts` (`SubscriptionSync` pushes debounced on changes). Storage is Upstash Redis through `lib/server/kv.ts` (env `UPSTASH_REDIS_REST_URL`/`_TOKEN` or `KV_REST_API_URL`/`_TOKEN`; in-memory Map in dev, 503 in production if unset). Two secrets: the public **token** (in the subscription URL, read-only) and the **secret** (write, only in the browser, stored server-side as sha256, Bearer auth). Routes: `POST /api/naptar`, `GET|PUT|DELETE /api/naptar/[token]`. On GET the server re-fetches the source feeds (cache `src:<token>:<feedId>`, 15 min), merges with `mergeFeedSync` and warns about feeds failing > 24 h. `subscription` and `exportOptions` are persisted but not part of `AppData`. iCal UIDs derive from `feedId` + `externalUid`, never from deadline ids. Views: `?nezet=osszes|kritikus|zh|targy-<courseId>` on the same token (`lib/ical/views.ts`, unknown → everything); `buildCalendar` also adds opt-in-by-default `weeklySummary` (all-day "Heti radar" on the Monday of 4 weeks) and `studyBlocks` (2 all-day days before open critical deadlines), both transparent; `ExportOptions` are defaulted on hydration (store `merge`) and in `validateSnapshot`. A feed-reported due change sets `previousDue`/`dueChangedAt` in `mergeFeedSync` and shows `módosult` for 48 h (`isRecentlyChanged`). `IcalFeed.markDoneBefore` makes deadlines created by a sync that were already past done. Everything date- or week-dependent in exports uses the Budapest helpers in `lib/ical/budapest.ts`, never the runtime's local time (the server is UTC).
- **Duplicates:** `lib/ical/dedupe.ts` (pure) finds the same deadline from several sources: different feeds (or manual + feed), same course, same Budapest day (±60 min when both are timed), similar titles (whole-token containment or token overlap ≥ 0.6, number guard so "Beadandó 02" ≠ "03"). Groups are **computed, never stored**; only the user's exceptions live in `AppData.ignoredDuplicatePairs` (pair keys of `deadlineIdentity`, which is `ical:<feedId>:<externalUid>` or `manual:<id>`, never the random server-side id). Primary by source priority manual > canvas > moodle > neptun > other. `ExportOptions.dedupe` (default on) governs the app lists too: use `useDedupedDeadlines()` (`lib/useDedupedDeadlines.ts`) for anything that lists or counts deadlines; `buildCalendar` dedupes before filtering the view and adds a "Források:" block. `toggleDone`/critical on a primary apply to its whole group.
- **Due-change record:** the server keeps `chg:<token>` (KV, `lib/server/dueChanges.ts`, pure `trackDueChanges`) so the 48 h "módosult" window starts when a move is first seen, not at every request. Seeded from the snapshot's deadlines, pruned per render, deleted with the subscription.
- **Timetable (Neptun):** `ClassSession` / `TimetableSource` in `AppData` (not deadlines: never in urgency, radar, notifications or dedup). `lib/ical/neptun.ts` parses the static `.ics` (`<subject> ( - <group>) - <teachers> - <type>`); there is ONE calendar import, in `FeedSettings` (link or .ics file): content decides the route via `isNeptunCalendar` (Neptun → timetable import through `components/settings/useTimetableImport.tsx` and `TimetableSourceItem`; otherwise a normal `IcalFeed`, which needs a link). A file is parsed in the browser, only a link goes through `/api/ical`. Only the current week and later are imported (`timetableCutoff`/`upcomingSessions`: Monday 00:00 Budapest of this week), so past semesters are never asked about, and a re-import purges stored past sessions. Subjects are mapped to courses once (`TimetableMappingDialog`, `subjectCourses`), the mapping survives re-imports. Export: view `?nezet=orarend`, `ExportOptions.includeClasses` (default off) for "összes"/course views; session UIDs derive from `sourceId` + `externalUid`. The snapshot carries `classSessions` (cap 1500); the server never re-fetches timetables. The home "Órák" toggle (`showClasses`) is a device preference, not in `AppData`.
- **Email digest (opt-in, needs the calendar subscription):** pure selection in `lib/digest.ts` (`collectDigest` dedupes and picks open overdue ≤ 14 days + open deadlines from today to the end of this week (daily: at least tomorrow) / calendar month, `digestRange`; daily also lists today's `classesToday` from the snapshot timetable and `shouldSendDigest` only sends it when something is due today or tomorrow; `digestPeriodKey` per Budapest day / Monday week / month). The mails are rendered in `lib/digestEmail.ts` as the notice board (heading on felt, day strips with paper slips whose pin carries state, salmon overdue block, canary feed warning, stamped "Kritikus"/"Módosult"): table layout with inlined light tokens copied from `app/tokens.css` (the one other place raw hex is allowed), a `<style>` block only for Archivo, a narrow-screen day column and the dark tokens under `prefers-color-scheme`. Server: `lib/server/digest.ts` (`dig:<token>` + the `dig:index` set, double opt-in with a hashed confirm key valid 48 h, raw unsubscribe key, `lastPeriod` so each period sends once), `lib/server/email.ts` (Resend via fetch, env `RESEND_API_KEY`/`DIGEST_FROM`; logs in dev). Routes: `GET|PUT|DELETE /api/naptar/[token]/hirlevel` (Bearer secret), `POST /api/hirlevel` (form from the `/hirlevel` page and RFC 8058 one-click; links only ever GET the page, never mutate), `GET /api/cron/hirlevel` (Vercel cron in `vercel.json`, `CRON_SECRET`). Live deadlines come from `loadLiveDeadlines` (`lib/server/calendar.ts`), shared with the .ics. Deleting the subscription deletes the digest. UI: `components/settings/DigestSettings.tsx` in the Értesítések tab.
- **Tests:** `npm test` runs `node:test` on `test/*.test.ts` (Node strips types; `test/alias-loader.mjs` resolves `@/` and extensions), with `TZ=UTC` on purpose (the server's zone). Fixtures are in `fixtures/ical`. Tests may only import modules free of React, zustand and `"use client"`.
- **Notifications:** pure logic in `lib/notifications.ts`, scheduler `components/NotificationScheduler.tsx` (only while a tab is open, no service worker); prefs and sent keys live in the store but are not part of `AppData`.
- **Settings page:** each section is its own component in `components/settings/`, rendered by `app/beallitasok/page.tsx` (the Naptárak tab holds `FeedSettings`, which also lists and imports Neptun timetables).
