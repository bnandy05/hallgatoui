# Project conventions

The current roadmap (what's done, what's next, open questions) is in `docs/PLAN.md`; read it at the start of a session and keep it updated. Real iCal exports for tests go in `fixtures/ical/` (scrubbed, see its README).

Hallgatói réteg: a per-course dashboard that sits on top of university systems (Neptun, Teams, Canvas, Moodle, TMS, Discord…).

- **Language (hu + en):** the UI exists in Hungarian and English; code, identifiers and comments are English. Routes stay Hungarian for both (`/`, `/targy/[id]`, `/radar`, `/beallitasok`). The brand name "Hallgatói réteg" is not translated.
- **i18n:** dictionaries are `lib/i18n/hu.ts` (source, `as const`, nested by area, functions for counts/variables) and `en.ts` (typed against `hu`, so a missing or extra key fails `npm run build`); `t` is the messages object itself (`t.nav.week`, `t.counts.deadlines(3)`). Client components use `useT()`/`useLocale()` (`I18nProvider` in the root layout), server components `getT()`/`getLocale()` (`lib/i18n/server.ts`), route handlers `requestLocale(req)` / `userLocale(user)` (`lib/server/locale.ts`) and `errorResponse(locale, code, status)` (JSON `{ error, code }`; clients branch on `code`, never on the text). No raw UI strings in components, and keep both languages in step. `pickLocale` (`lib/i18n/locales.ts`, pure) gives Hungarian only when `hu` is the highest-ranked Accept-Language, else English; `proxy.ts` sets the `hr_lang` cookie (1 year, not httpOnly) when it is missing, also on the public pages. The account stores `locale` + `localeExplicit` (missing = `hu`, not explicit): registration takes the cookie language; at sign-in an explicit choice wins and sets the cookie, otherwise the account follows the browser. `PUT /api/fiok/nyelv` stores an explicit choice and drops the user's .ics cache. **Mails, the subscribed .ics and server errors use the account language** (cookie when signed out). `useSetLanguage` (`lib/i18n/useSetLanguage.ts`) is the one switching path: cookie, account call when signed in, clears the service worker's page cache, `router.refresh()`; controls are in Beállítások → Megjelenés and `LanguageToggle` on the sign-in page. Dates: `dateLocale(locale)` plus the format strings in `t.formats` (en-GB: `d MMM`, 24 h); pure libs take an optional `locale` (default `hu`) and stay React-free; built-in platform/resource-kind names are translated at display time (`platformName`, `t.resourceKinds`), names written into user data at creation use the current language. `parseQuickDeadline` accepts Hungarian and English keywords whatever the UI language. Non-obvious: `parseIcs`' untitled fallback is display-only (the key never depends on the language); fetch errors are `IcalError` codes.
- **Accounts (server is the source of truth):** sign-in is required (email + password, or magic link; the email must be confirmed). Hand-rolled auth on `node:crypto` (`lib/server/auth/*`: scrypt, tokens stored as sha256, `hr_session` httpOnly cookie, Origin check on mutating routes) behind the `AccountStore` interface (`lib/server/account/store.ts`; `memoryStore` for dev and tests, `redisStore` for Upstash; records and keys in `docs/superpowers/specs/2026-10-05-accounts-design.md`). Routes: `/api/fiok*` (register, sign-in, links, password, email, delete; `/api/fiok/naptar`, `/api/fiok/hirlevel`), `/api/adatok` (one versioned data document per user, compare-and-set, 409 returns the remote). `proxy.ts` redirects app pages without a session cookie to `/belepes` (optimistic only; the API is the real gate). The client keeps the zustand store `lib/store.ts` as the in-memory model and a localStorage cache (`hallgatoireteg-v2`, with `ownerUserId`); `components/AccountSync.tsx` + `lib/sync/*` push debounced changes and pull on focus, merging three-way on conflict (`mergeAppData`). Types are in `lib/types.ts`. Select slices individually: `useStore((s) => s.courses)`. Storage and Resend are needed in production (503 without).
- **Demo (no account):** `lib/demoMode.ts` (`hr_demo` session cookie, `enterDemo`/`leaveDemo`/`registerFromDemo`, `isDemoMode`, `useDemoMode()` in `lib/useDemoMode.ts`). Client-only: in the demo the store caches into sessionStorage (`hallgatoireteg-demo`), `startDemo` seeds `buildShowcaseData` owned by `DEMO_USER_ID`, no sync, no `/api/fiok*` or `/api/adatok` calls, demo feeds (`demo-…`) are never fetched; signing in ends it (`dropForeignCache`). Anything that needs an account renders `DemoLocked` (`components/demo/NeedsAccount.tsx`) in the demo. The guide's steps are in `components/demo/DemoTour.tsx` (targets are `data-tour` attributes, texts in the dictionary's `demo` group); keep it in step when pages change.
- **Hydration:** components that read the store are client components and render a skeleton until `useHydrated()` (`lib/useHydrated.ts`) returns true for device preferences, or `useDataReady()` (`lib/useDataReady.ts`) once the store holds this user's data.
- **Dynamic routes:** `page.tsx` is a thin server component that awaits `params` (typed with `PageProps<"/route/[id]">`) and renders a client component (e.g. `app/targy/[id]/page.tsx` → `components/week/CourseWeekDetail.tsx`).
- **UI:** Tailwind v4 with the color tokens from `app/globals.css` (`bg-card`, `border-border`, `text-muted`, `bg-accent`, `text-danger`…). Build from `components/ui/*` and use `lucide-react` icons. No component libraries, and no new dependencies without asking.
- **Platforms:** built-in platforms are in `lib/platforms.ts`, and user-defined ones in `customPlatforms`. Always resolve them with `getPlatform(id, customPlatforms)`. Normalise user URLs with `normalizeLinkUrl` (`lib/url.ts`).
- **Deadlines:** urgency, week grouping and the weekly summary are pure functions in `lib/radar.ts` (weeks start on Monday). Reuse them; don't recompute urgency in components. Deadlines with `source: "ical"` can't be edited or deleted, only marked done or critical.
- **iCal:** `app/api/ical/route.ts` is a CORS proxy that requires a session and is rate limited per user (fetching lives in `lib/ical/fetch.ts`, shared with the subscription routes). Every URL, and every redirect hop, must pass `assertPublicUrl` (`lib/ical/ssrf.ts`); never remove that check or switch to `redirect: "follow"`. Parsing (`lib/ical/parse.ts`) and course matching (`lib/ical/match.ts`) are pure functions. Sync goes through `lib/ical/client.ts` → the store's `applyFeedSync` (a thin wrapper over the pure `mergeFeedSync` in `lib/ical/sync.ts`, also used by the server), which upserts by `(feedId, externalUid)` and keeps the user's `done`/`critical`/course choices. Canvas context parsing lives in `lib/ical/canvas.ts`, discovery in `lib/ical/discover.ts` + the store's `applyDiscovery`; every sync also runs `autoLinkContexts`, which adds a context's Canvas course link to the course it already belongs to (fixed course or keyword match) once, remembered in `IcalFeed.linkedContexts` so a deleted link stays deleted; matching is longest-keyword-wins.
- **Search & quick-add:** search lives in `lib/search.ts` + `components/CommandPalette.tsx`, the quick-add parser in `lib/quickAdd.ts`; matching is accent-insensitive via `normalizeSearch` (`lib/text.ts`).
- **Dialogs:** `components/ui/Dialog.tsx` mounts its children only while open, so forms inside it initialise from props with `useState(initial…)`. Never `confirm()`: destructive or irreversible actions ask with `useConfirm()` (`components/ui/ConfirmDialog.tsx`: `const { confirm, dialog } = useConfirm()`, render `{dialog}` once, `if (await confirm({ title, message?, confirmLabel, tone? }))`; `tone` is `"danger"` (default) or `"default"`). A single deadline is deleted without asking, behind the undo toast (`lib/useDeadlineUndo.ts`, `components/ui/Toast.tsx`)..
- **Design system:** "Hirdetőtábla" (faculty notice board), in daylight (light) and after hours (dark). Tokens in `app/tokens.css`, one block per theme on `[data-theme]` (light is `:root`); hover tints use `bg-wash/[…]`, never `bg-black/…`; shadows, backdrop and canvas inks are tokens too. The preference (`theme`: system | light | dark, default system) is a store device preference, applied before paint by `THEME_SCRIPT` (`lib/theme.ts`) in the root layout and kept in sync by `ThemeSync`; toggle in the header (`ThemeToggle`) and Beállítások → Megjelenés (felt `--bg`, copy-paper `--panel`, toner `--accent` for primary buttons and active controls with `text-accent-ink` on it, red `--pin` / `--danger` only for now, late, critical and destructive, coloured papers `--canary` (today, highlight), `--salmon` (overdue), `--sky` (classes)), mapped to Tailwind colours in `globals.css`. Font: Archivo via next/font; headings use `.font-display` (condensed, heavy). Primitives in `globals.css`: `.pin` (round head, colour via `--pin-color`), `.slip` (a pinned paper slip; `data-done` unpins and tilts it), `.sheet-paper`. Deadlines on boards are `DeadlineChip` slips whose pin carries state (course colour, red when hot, gone when done). Pages use `SectionHeading` (title + optional sub + actions; no eyebrows or kickers), `Card`, `Pill`, `Dialog`, `EmptyState` from `components/ui/`; `PinboardField` is the canvas background (one faint slip per open deadline, each in a fixed slot; ticking off takes the latest down, unticking or adding pins one up). No raw hex outside user/course/platform data and `PinboardField`; no gradients, glows or glass; copy is concise, professional Hungarian with no jokey asides; respect `prefers-reduced-motion`.
- **Calendar subscription (account-owned, opt-in):** `buildCalendar` (`lib/ical/export.ts`, pure, ical.js) renders one merged .ics; `downloadCalendar()` does it in the browser with no server. Turning the subscription on creates a public read-only **token** (`/api/fiok/naptar`, stored as `sub:<token>` → `{ userId }` and on the user; `?uj=1` rotates, DELETE turns off); there is no secret and no snapshot upload: the server renders from the account's data document. `GET /api/naptar/[token]` (public) → `renderCalendar(store, userId, now, appUrl, view)` in `lib/server/calendar.ts` (in the account's language: `buildCalendar` takes `locale` for every text, calendar names in `lib/ical/views.ts`, texts in the dictionary's `ics` group; the browser download uses the UI language), which builds the input with `calendarInput(doc)` (`lib/server/calendarInput.ts`: course links/resources stripped, timetable via `visibleSessions`, capped at 1500), re-fetches the source feeds through `loadLiveDeadlines(kv, userId, input, now)` (cache `src:<userId>:<feedId>`, 15 min), merges with `mergeFeedSync`, warns about feeds failing > 24 h, and caches the result as `ics:<userId>:<locale>:<view>` (15 min, listed in `icsk:<userId>`); every successful data save (`saveData`) and every language change deletes those (`dropRenderedCalendars`), so edits show at once. **Event actions:** an open deadline's description carries "Késznek jelölöm" (`/?kesz=<deadlineIdentity>`, handled by `components/MarkDoneLink.tsx`: confirm, then the undo toast) and, for a class or deadline tied to a tracked requirement component without a result, "Eredmény rögzítése" (`/?potlas=<catchUpGroupKey>`, `CatchUpGate` opens just that group or says there is nothing to record); links only open the app, never change anything. With `ExportOptions.gradeInfo` (default on) a linked assessment within 60 days also gets a "Jegyek:" block from `assessmentNotes` (`lib/gradeAlerts.ts`, the same opportunity and hard-pass texts as the alerts); `buildCalendar` takes the tracker data as `requirements` (`calendarInput` passes the account's rules, results and semester). Views: `?nezet=osszes|kritikus|zh|orarend|targy-<courseId>` (`lib/ical/views.ts`, unknown → everything); `buildCalendar` also adds opt-in-by-default `weeklySummary` (all-day "Heti radar" / "Weekly radar" on the Monday of 4 weeks) and `studyBlocks` (2 all-day days before open critical deadlines), both transparent; `ExportOptions` live in the data document and are defaulted by `validateExportOptions`. A feed-reported due change sets `previousDue`/`dueChangedAt` in `mergeFeedSync` and shows `módosult` for 48 h (`isRecentlyChanged`). `IcalFeed.markDoneBefore` makes deadlines created by a sync that were already past done. Everything date- or week-dependent in exports uses the Budapest helpers in `lib/ical/budapest.ts`, never the runtime's local time (the server is UTC). iCal UIDs derive from `feedId` + `externalUid`, never from deadline ids.
- **Duplicates:** `lib/ical/dedupe.ts` (pure) finds the same deadline from several sources: different feeds (or manual + feed), same course, same Budapest day (±60 min when both are timed), similar titles (whole-token containment or token overlap ≥ 0.6, number guard so "Beadandó 02" ≠ "03"). Groups are **computed, never stored**; only the user's exceptions live in `AppData.ignoredDuplicatePairs` (pair keys of `deadlineIdentity`, which is `ical:<feedId>:<externalUid>` or `manual:<id>`, never the random server-side id). Primary by source priority manual > canvas > moodle > neptun > other. `ExportOptions.dedupe` (default on) governs the app lists too: use `useDedupedDeadlines()` (`lib/useDedupedDeadlines.ts`) for anything that lists or counts deadlines; `buildCalendar` dedupes before filtering the view and adds a "Források:" block. `toggleDone`/critical on a primary apply to its whole group.
- **Due-change record:** the server keeps `chg:<userId>` (KV, `lib/server/dueChanges.ts`, pure `trackDueChanges`) so the 48 h "módosult" window starts when a move is first seen, not at every request. Seeded from the account's deadlines, pruned per render, deleted with the account.
- **Timetable (Neptun):** `ClassSession` / `TimetableSource` in `AppData` (not deadlines: never in urgency, radar, notifications or dedup). `lib/ical/neptun.ts` parses the static `.ics` (`<subject> ( - <group>) - <teachers> - <type>`); there is ONE calendar import, in `FeedSettings` (link or .ics file): content decides the route via `isNeptunCalendar` (Neptun → timetable import through `components/settings/useTimetableImport.tsx` and `TimetableSourceItem`; otherwise a normal `IcalFeed`, which needs a link). A file is parsed in the browser, only a link goes through `/api/ical`. The whole current semester is imported, past weeks included (`importFloor` in `lib/ical/neptun.ts`: the semester's first Monday is detected by `proposeSemesterStartAt` as the start after the last break of at least 3 weeks, and a stored `AppData.semester.start` counts only when it is the same term; the floor is never later than this week's Monday, so exam-period exams still come in, and never more than half a year back; `upcomingSessions` filters with it); earlier terms in the export are never imported or asked about. The semester start is asked when none is stored or the stored one is from a previous term (`isStaleSemester`; `SemesterStep` in `useTimetableImport.tsx`); "Kihagyás" still imports from the detected floor, which `importTimetable` receives as `meta.from`. `timetableCutoff` (this week's Monday) remains the "tracked since" date of catch-up; a re-import keeps this semester's stored past sessions (back to the semester start, at most half a year: results refer to them). Subjects are mapped to courses once (`TimetableMappingDialog`, `subjectCourses`), the mapping survives re-imports; a subject can be mapped per Neptun group (key `subjectKey|group`, Ea and Gy as two courses, the default for new subjects with several groups); always resolve a session's course with `mappedCourse`, and apply dialog results with `applyMappingDecisions`. Export: view `?nezet=orarend`, `ExportOptions.includeClasses` (default off) for "összes"/course views; session UIDs derive from `sourceId` + `externalUid`. The data document carries `classSessions` (cap 1500); the server never re-fetches timetables. The home "Órák" toggle (`showClasses`) is a device preference, not in `AppData`.
- **Jev suggestions:** only for what local rules can't settle, and every answer cached. Course for a name (`lib/suggest/courseMatch.ts`, pure `guessCourse`: equal name ignoring accents/dots/Ea-Gy-Lab suffix, keyword or course code, one clearly closest name; different numbers never match; else `{ ask }`) feeds the defaults in `TimetableMappingDialog` and `DiscoveryDialog` through `useCourseSuggestions` (a confirmed Canvas mapping becomes a keyword, so it is never asked again; `SuggestionNote` says when a default is a guess). Grade components: `localDeadlineMatches` (`lib/suggest/componentMatch.ts`) adds a number guard between sibling components ("1. zh" / "2. zh") to `suggestDeadlineLinks`; only when it finds nothing does `ComponentLinkDialog` ask Jev which component each of the course's latest 20 deadlines belongs to. Duplicates: `borderlinePairs` (`lib/ical/dedupe.ts`) lists pairs whose titles are neither similar nor clearly different; `components/DuplicateCheck.tsx` asks about upcoming ones once per device and stores a "same" as a `CONFIRMED_PREFIX` ("=") entry in `ignoredDuplicatePairs` (a plain entry, the user's exception, always wins; `userExceptions` for counts). Server: `POST /api/javaslat` builds the questions itself (`lib/suggest/questions.ts`, no ids), `suggestWithJev` (`lib/server/jevSuggest.ts`) caches every answer for everyone under a hash of the question (`jevc:`, 30 days) and counts only uncached questions (`rl:jev:d:<userId>`, 150/day); errors are `errorResponse(locale, code, status)` like every route. The browser side (`lib/suggest/client.ts`) treats every failure as "no suggestion" and **never calls the server in the demo** (`isDemoMode()`).
- **Course requirements (the tracker):** the "Követelmények" section on the course page (`components/RequirementsSection.tsx`) holds `Course.requirements` (free text, capped at `MAX_REQUIREMENTS_CHARS` in `parseAppData`) and requirement documents, which are resources of kind `kovetelmeny`, hidden from `ResourceList`; the calendar and digest strip the text. **Rules and results:** `AppData.requirementRules` (one validated `SubjectRules` per course, id `rules:<courseId>`, merged as one block by `mergeWhole`) and `AppData.requirementResults` (deterministic ids `courseId|componentId|instanceKey`, field-merged, capped at `MAX_REQUIREMENT_RESULTS`); types in `lib/rules/types.ts`, formulas parsed by `lib/rules/expr.ts`, `validateRules` (`lib/rules/validate.ts`) guards every import, `evaluate` (`lib/rules/engine.ts`) gives each grade's best/worst/status and gates, `solveFor` (`lib/rules/solve.ts`) answers "mi kell a jegyhez", `courseStanding` (`lib/rules/standing.ts`) the one-line standing and risk, templates in `lib/rules/fixtures.ts`; all pure and never storing results inside the rules or keying them by index. **Language:** these libraries take an optional `locale` (default `hu`) and get their wording from the dictionary's `rules` group (`lib/i18n/rules.hu.ts` / `rules.en.ts`, mounted as `t.rules`); the extraction lexicon and patterns stay Hungarian on purpose (they read Hungarian documents) and so do the Jev prompts, component labels from a document and fixtures. Text stored inside data is not translated in place: a review flag (`RuleFlag`) stores a stable `code` + `args` with the Hungarian `message` as fallback (`flagFor`, `lib/rules/flags.ts`, so a shared template's hash does not depend on the reading language) and is shown with `flagText(flag, locale)`; a result's `label` is a display snapshot in the language of the moment, never parsed. The tracker's UI texts are in `lib/i18n/tracker.hu.ts` / `tracker.en.ts` (spread into the dictionary; groups `rulesPanel`, `rulesBreakdown`, `surveyForm`, `extractDialog`, `catchUp`, `linkedComponent`, `componentLink`, `resultInputs`, `university`…). Numbers shown to the reader go through `formatNumber(n, locale)` (decimal comma only in Hungarian). **Setting rules up** (`components/requirements/RulesPanel.tsx`, three ways, none of them needs Jev): from the requirements document (`ExtractDialog.tsx`: a PDF read in the browser by pdf.js, `pdfText.ts`, or pasted text), from a template (`RULE_TEMPLATES` or a shared one), or **by hand**: "Kitöltés kézzel" opens the survey form from `emptySurvey()`, "Saját szabályok (JSON)" the validated JSON editor. The rules sheet is laid out from the rules alone: `RulesPanel` (standing rulers, the "Ellenőrizd" slip, the results ledger grouped by kind, the solver), `RulesBreakdown.tsx` ("Így számoljuk"), `LinkedComponent.tsx` (one ledger row), `ResultInputs.tsx` / `InstanceInput.tsx` (inputs) and `RulesPreview.tsx`; always generated from the rules, never per template. **Extraction, the survey:** `POST /api/kovetelmeny/elemzes` (`{ text, course: { name, code? } }`; session, verified email, 10/hour and 30/day limits; 502 when Jev fails, 503 without a key) has Jev (TypeSafe System One, `systemOne` in `lib/server/jev.ts`, env `JEV_API_KEY`, model `SURVEY_MODEL`) read the whole document once: `buildSurveyRequest` (`lib/rules/extract/survey/questions.ts`) makes 24 independent typed questions (Noul for yes/no, Choice over fixed labels for structure and counts, Choice over `none` + every number candidate for points; the wording is the owner's tested prompt, change it only after a live run against the fixtures; at most `SURVEY_MAX_DOC_CHARS` = 40 000 characters). **Jev picks, code builds:** numbers are never generated, `numberCandidates` finds them and the answer is copied from the document. The raw answers are cached for everyone as `jevs:<sha256 of the request body, first 40 hex>` (30 days; labels and numbers only, never text). `readSurvey` (`read.ts`, pure, defensive) turns the answers into a `SurveyDraft` (`value`, `flagged`, `reasons`, `quote`, `hidden`): flags from probabilities (`CHOICE_REVIEW_BELOW`, `NOUL_REVIEW_BAND`), a number that is an upper end picked for a lower end, gates (`GATES` in `fields.ts`) and `consistency` checks, which flag and never fix. `surveyRules` builds `SubjectRules` from the confirmed form, runs `validateRules` and `semanticErrors` and gives errors instead of rules when it cannot; **a result that fails the checks is never saved**. The `SurveyForm` (an `xl` dialog: form beside a sticky preview; flagged fields on canary paper with the quote and "Rendben"; saving blocked until nothing is unconfirmed) is the review for Jev's reading and, from `emptySurvey()`, the hand setup. When Jev is unavailable (503, 429, 502, network) **and always in the demo** the pattern parser `extractRules(text, answers, now, locale)` (`lib/rules/extract/*`) runs in the browser; if it rejects the text the form starts empty with a one-line reason. Fixtures: `fixtures/kovetelmeny/<name>/survey.json` and real Jev answers in `fixtures/kovetelmeny/jev-valaszok/` (`test/surveyRealAnswers.test.ts` holds the accuracy bar); eval with `npm run jev:survey -- <doc.txt> "<course>" [expected.json] [--dry]`. Every new pattern needs a fixture sentence and must keep `test/rulesExtract.test.ts` green. **Shared templates and the university:** `tpl:<university>:<code>:<semester>` in KV (pure logic `lib/rules/shared.ts`, storage `lib/server/ruleTemplates.ts`, routes `/api/kovetelmeny/sablon` and `/api/fiok/egyetem` for `uni:<userId>`); variants keyed by `rulesHash`, confirmers stored as hashed ids (`tplu:<userId>` indexes them so `deleteAccount` removes them), notes stripped, the previous term offered as a fallback; the empty rules panel offers one before extraction (`SharedTemplate.tsx`), the university is chosen in Beállítások → Fiók (`UniversitySettings.tsx`). **Privacy and terms:** the notice (`lib/privacy.ts`) names the Jev processor and its constants (`JEV_PROCESSOR`, `JEV_MAX_TEXT_CHARS`, `JEV_CACHE_DAYS`, `JEV_COUNTER_HOURS` in `lib/legal.ts`), the requirement/result data under "Tanulmányi adatok" and the shared templates; the terms say that the AI reading is a suggestion the student confirms, that computed grades carry no guarantee and that shared templates are user-contributed. The notice also promises that rules can be set up without Jev, so the by-hand path must stay.
- **Requirement links, catch-up, reminders:** a component (or retake slot) is tied to the calendar by `RequirementRules.calendarLinks[componentId]` (`ComponentLink` in `lib/rules/links.ts`: `sessions` with a group/weekday/week selector and limit, `weeks`, or picked `deadlines` by `deadlineIdentity`; validated by `linksFrom`, kept when the rules are edited, never part of a shared template). **Auto links:** `components/RequirementAutoLink.tsx` (after this tab's first server pull) runs `autoLinks` whenever the rules, the timetable or the (deduped) deadlines change, for every component with no link that is not in `RequirementRules.autoLinked` (the ids it linked or the user set/removed by hand via `setComponentLink`, so a removed link stays removed; applied with `applyAutoLinks`, `since` = this week's Monday; a series or attendance that already has numbered `n:` results is left alone): `defaultLinks` (attendance → every class, a röpzh series → every class from week 2; only when the course's classes are all one Neptun group) and `defaultDeadlineLinks` (a component whose label names its kind takes the course's deadlines with that word, by number when exactly one fits, else in due order when the counts match; a quiz series takes the quiz deadlines when there are exactly `count`). `resolveInstances` (`lib/rules/instances.ts`) gives the instances with stable keys (`s:<Neptun UID>`, `w:<week>`, `d:<identity>`; single-result components always `n:1`), pins instances that have a result but are no longer selected, and marks those after the link's `since` as tracked; labels come from `instanceLabel(instance, locale)`, snapshots from `instanceSnapshot`. Week numbers come from `AppData.semester` (`lib/timetable/semester.ts`, Budapest Mondays; merged latest-edit-wins; `SemesterField`). `lib/catchup.ts` (pure, also used by the digest): `pendingInputs` (ended, tracked, no result; grouped per class or deadline), `awaitingResults` ("Még nincs eredmény", late after 14 days), `upcomingAssessments`, `shouldPrompt` against the account-wide `AppData.catchUp.promptedUntil` (merged as the later). UI: `components/catchup/CatchUpGate.tsx` (opens after this tab's first server pull, `pulledThisSession`, so never by itself in the demo; also from `openCatchUp()` or the digest's `/?potlas=1`) + `CatchUpDialog.tsx` (the quick path: the first score field has focus, Enter moves to the next empty one and finishes after the last; "Kész" marks every score left empty on the pages seen as pending, i.e. "Eredményre vár" in the bell (`canAwait`); X leaves them unrecorded); `LinkedComponent.tsx`, `ComponentLinkDialog.tsx`, `InstanceInput.tsx` on the course page; `components/RemindersMenu.tsx` (header bell, keeps `data-tour="reminders"`, pure `buildReminders` in `lib/reminders.ts`, nothing stored; a pending class or test with at most two fields is filled in inside the bell, "Még nincs" marks it pending; a "Figyelem" section lists the grade alerts, danger ones counted in the badge); `courseStanding` is shown on the home course cards once the course has a recorded result; a "Rögzítésre vár" block in the digest (`digestPendingFrom` in `lib/server/digest.ts`, texts in the dictionary's `email` group; a daily mail also goes out for an unrecorded class since yesterday); an in-tab notice 30 min after the day's last linked class (`catchUpNotification`). Web Push is later (owner decision). Confirmations use `const { confirm, dialog } = useConfirm()` (render `{dialog}` once).
- **Demo and the tracker:** the demo's course "Analízis I." carries the Calculus template's rules and a few results (`lib/demoRules.ts`, labels translated by id for English, used by `buildShowcaseData`), and the guide has a step for the course page's requirements section (`data-tour="requirements"`, texts in the `demo` group). Server-backed parts never run there: the Jev survey falls back to the pattern parser, suggestions return nothing, shared templates are not looked up, and the university setting lives in the (locked) account tab.
- **Grade alerts (logic, preferences, bell, settings, email):** `gradeAlerts(input, locale)` (`lib/gradeAlerts.ts`, pure, input = `CatchUpInput`) returns `GradeAlert`s (`key`, `kind`, `severity` info|warning|danger, `courseId`, localised `text`, optional `due`, `urgent`), sorted danger → warning → info, then date, then key (`compareAlerts`); `filterAlerts(alerts, kinds)` keeps the kinds switched on.
