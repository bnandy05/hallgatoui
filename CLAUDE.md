# Project conventions

Hallgatói réteg: a per-course dashboard that sits on top of university systems (Neptun, Teams, Canvas, Moodle, TMS, Discord…).

- **Language:** all UI text is Hungarian; code, identifiers and comments are English. Routes are Hungarian (`/`, `/targy/[id]`, `/radar`, `/beallitasok`).
- **Local-first:** no accounts, no auth. All data lives in the zustand store `lib/store.ts`, persisted to localStorage (`hallgatoireteg-v1`). Types are in `lib/types.ts`. Select slices individually: `useStore((s) => s.courses)`.
- **Hydration:** components that read the store are client components and render a skeleton until `useHydrated()` (`lib/useHydrated.ts`) returns true.
- **Dynamic routes:** `page.tsx` is a thin server component that awaits `params` (typed with `PageProps<"/route/[id]">`) and renders a client component (e.g. `app/targy/[id]/page.tsx` → `components/CourseDetail.tsx`).
- **UI:** Tailwind v4 with the color tokens from `app/globals.css` (`bg-card`, `border-border`, `text-muted`, `bg-accent`, `text-danger`…). Build from `components/ui/*` and use `lucide-react` icons. No component libraries, and no new dependencies without asking.
- **Platforms:** built-in platforms are in `lib/platforms.ts`, and user-defined ones in `customPlatforms`. Always resolve them with `getPlatform(id, customPlatforms)`. Normalise user URLs with `normalizeLinkUrl` (`lib/url.ts`).
- **Deadlines:** urgency, week grouping and the weekly summary are pure functions in `lib/radar.ts` (weeks start on Monday). Reuse them; don't recompute urgency in components. Deadlines with `source: "ical"` can't be edited or deleted, only marked done or critical.
- **iCal:** `app/api/ical/route.ts` is a CORS proxy (fetching lives in `lib/ical/fetch.ts`, shared with the subscription routes). Every URL, and every redirect hop, must pass `assertPublicUrl` (`lib/ical/ssrf.ts`); never remove that check or switch to `redirect: "follow"`. Parsing (`lib/ical/parse.ts`) and course matching (`lib/ical/match.ts`) are pure functions. Sync goes through `lib/ical/client.ts` → the store's `applyFeedSync` (a thin wrapper over the pure `mergeFeedSync` in `lib/ical/sync.ts`, also used by the server), which upserts by `(feedId, externalUid)` and keeps the user's `done`/`critical`/course choices. Canvas context parsing lives in `lib/ical/canvas.ts`, discovery in `lib/ical/discover.ts` + the store's `applyDiscovery`; matching is longest-keyword-wins.
- **Search & quick-add:** search lives in `lib/search.ts` + `components/CommandPalette.tsx`, the quick-add parser in `lib/quickAdd.ts`; matching is accent-insensitive via `normalizeSearch` (`lib/text.ts`).
- **Dialogs:** `components/ui/Dialog.tsx` mounts its children only while open, so forms inside it initialise from props with `useState(initial…)`.
- **Design system:** tokens live in `app/tokens.css` (Odysseus-derived dark theme, monospace Fira Code), mapped to Tailwind colours in `globals.css`; pages use `SectionHeading` (eyebrow + heading), `Card`, `Pill`, `Terminal`, `CodeBlock`, `Reveal`, `FlowField` from `components/ui/`; no raw hex colours outside user/course/platform data; respect `prefers-reduced-motion`.
- **Calendar subscription (the only server state, opt-in):** `buildCalendar` (`lib/ical/export.ts`, pure, ical.js) renders one merged .ics; `downloadCalendar()` does it in the browser with no server. Subscribing uploads a snapshot (courses, deadlines, feeds, customPlatforms, export options) via `lib/subscription/client.ts` (`SubscriptionSync` pushes debounced on changes). Storage is Upstash Redis through `lib/server/kv.ts` (env `UPSTASH_REDIS_REST_URL`/`_TOKEN` or `KV_REST_API_URL`/`_TOKEN`; in-memory Map in dev, 503 in production if unset). Two secrets: the public **token** (in the subscription URL, read-only) and the **secret** (write, only in the browser, stored server-side as sha256, Bearer auth). Routes: `POST /api/naptar`, `GET|PUT|DELETE /api/naptar/[token]`. On GET the server re-fetches the source feeds (cache `src:<token>:<feedId>`, 15 min), merges with `mergeFeedSync` and warns about feeds failing > 24 h. `subscription` and `exportOptions` are persisted but not part of `AppData`. iCal UIDs derive from `feedId` + `externalUid`, never from deadline ids. Views: `?nezet=osszes|kritikus|zh|targy-<courseId>` on the same token (`lib/ical/views.ts`, unknown → everything); `buildCalendar` also adds opt-in-by-default `weeklySummary` (all-day "Heti radar" on the Monday of 4 weeks) and `studyBlocks` (2 all-day days before open critical deadlines), both transparent; `ExportOptions` are defaulted on hydration (store `merge`) and in `validateSnapshot`. A feed-reported due change sets `previousDue`/`dueChangedAt` in `mergeFeedSync` and shows `módosult` for 48 h (`isRecentlyChanged`). `IcalFeed.markDoneBefore` makes deadlines created by a sync that were already past done. Everything date- or week-dependent in exports uses the Budapest helpers in `lib/ical/budapest.ts`, never the runtime's local time (the server is UTC).
- **Notifications:** pure logic in `lib/notifications.ts`, scheduler `components/NotificationScheduler.tsx` (only while a tab is open, no service worker); prefs and sent keys live in the store but are not part of `AppData`.
- **Settings page:** each section is its own component in `components/settings/`, rendered by `app/beallitasok/page.tsx`.
